# VoiceDock for Mac

**DJI Mic 3 で録音した音声を Mac へ挿すだけで、文字起こし・要約して Obsidian に残す。**

```text
DJI Mic 3 で録音 → 帰宅 → Mac へ USB 接続 → （以降すべて自動）
```

挿したあとに人がすることはありません。取り込み・16 kHz への変換・文字起こし・要約・ノートの作成は、メニューバーに常駐するアプリが Mac の中で順に進めます。

**クラウドの AI は使いません。音声もテキストも外部へ出ません。**
外部へ出さないことは方針としてだけでなく、テストで強制しています（ネットワークを使うのはモデルのダウンロードだけで、そこ以外の経路が無いことを静的検査が見ています）。

## 何が動いているか

| 工程 | 使うもの |
|---|---|
| デバイスの読み取り・コピー | VoiceDock 本体（macOS の標準機能だけ） |
| 16 kHz への変換 | AVFoundation（Mac 内蔵） |
| 文字起こし | whisper.cpp（Metal） |
| 要約・タスク抽出 | llama.cpp の `llama-server`（Metal） |
| ノート生成 | VoiceDock 本体 |
| 元音声の削除 | `voicedock-reaper`（**既定では導入されない**別の実行ファイル） |

メニューバーに常駐し、Dock には出ません。

## 必要なもの

| | |
|---|---|
| Mac | Apple Silicon、macOS 15.0 以上 |
| メモリ | 選べる LLM がメモリ量で決まる。既定のモデルは 32 GB 以上 |
| ディスク | モデルに 3〜20 GB、作業領域に数 GB |
| Obsidian | Vault を 1 つ作り、**一度 Obsidian で開いておく**（`.obsidian` が作られる） |

**使い始める前に、デバイスのボリューム名を決めてください。**
VoiceDock が取り込むのは、名前が `DJIMIC3` のデバイスだけです（既定。設定の `device.includeVolumes` で変えられます）。
取り込みの後にボリューム名を変えると、それ以前に取り込んだ録音は削除の対象から永久に外れます（録音が消えない側なので事故にはなりませんが、後から名前を戻しても戻りません）。
`NO NAME` のままなら、Finder かディスクユーティリティで改名してから使い始めてください。**アプリはデバイスに書き込まないので、改名はアプリからは行えません。**
名前が違うデバイスをつなぐと、パネルの「はじめに」に改名の手順が出ます（取り込みはしません）。

## インストール

### 1. dmg から入れる

`VoiceDock-<版>.dmg` を開き、`VoiceDock` を `Applications` へドラッグします。
配布物は Apple の公証を受けています。初回起動で警告が出る場合は、いったん dmg を閉じて開き直してください。

### 2. 最初の起動と、許可の出し方

`Applications` から `VoiceDock` を開くと、メニューバーにアイコンが出てパネルが自動で開きます。macOS の許可は次の 3 つです。

1. **リムーバブルボリューム**: 初めてデバイスを挿したときに「VoiceDock がリムーバブルボリューム上のファイルにアクセスしようとしています」と出ます。**「許可」を押してください。**
   ダイアログには `録音デバイスから音声を読み込むために使います` と説明が出ます。
   - 拒否した場合は、ここで許可し直します: `システム設定 → プライバシーとセキュリティ → ファイルとフォルダ → VoiceDock → リムーバブルボリューム`
   - パネルの「要対応」にも、この画面を開く「システム設定を開く」のボタンが出ます
2. **Vault のあるフォルダ**: Vault を書類・デスクトップ・ダウンロードのどれかに置いていると、同じ形の許可を求められることがあります。説明は
   `Obsidian の保管庫がこのフォルダにある場合に、ノートを書き込むために使います`
   です。Vault を使えないときは、パネルの「要対応」に「ファイルとフォルダ」の案内が出ます
3. **ログイン時に起動**: 「はじめに」の 4 つ目で選びます。システム設定の「ログイン項目」に承認待ちが出た場合は、パネルの「システム設定を開く」から開いて許可してください。
   アプリを `Applications` に置いていないと登録できません

**許可はアプリの署名に結び付いています。**配布物を入れ替える（新しい版に更新する）と、許可はそのまま引き継がれます。
自分でビルドしたものと配布物を行き来すると、許可を出し直すことがあります。

### 3. 「はじめに」を上から済ませる

パネルの「はじめに」に 5 つの項目が並びます。上から順に済ませてください。済んだ項目にはチェックが付き、未完了の項目が無くなると「はじめに」は消えます。

1. **Vault を選ぶ**: 「保存先（Vault）」の「変更…」で、Obsidian の Vault のフォルダ（`.obsidian` があるフォルダ）を選びます
2. **Whisper モデルを入手する**: 「モデル」の Whisper モデル（と VAD モデル）の「入手する」を押します
3. **LLM を選んで入手する**: 「モデル」の LLM モデルを選んで「入手する」を押します。メモリが足りないモデルは選べません。手元の `.gguf` は「ファイルから読み込む…」で取り込めます
4. **ログイン時に起動する**: スイッチを入れるか、使わないなら「今はしない」を押します
5. **デバイスの名前を変える**: 名前が `DJIMIC3` でないデバイスがつながっているときだけ出ます（完了にはならず、つなぎ直すと消えます）。手順が表示されます

モデルのダウンロードは数 GB あり、時間がかかります。途中で「やめる」を押してもよく、もう一度「入手する」を押すと続きから再開します（アプリを終了しても続きから再開できます）。

## 使い方

**録って、挿す。以上です。**

```text
1. DJI Mic 3 で録音する
2. Mac へ USB で挿す
3. 待つ（メニューバーのアイコンが動く）
4. Obsidian にノートが増える
```

**コピーが終われば抜いて大丈夫です。**以降の処理は Mac にコピーしたファイルから進みます。
**接続すると録音は自動的に停止します**（DJI Mic 3 の仕様）。録音中に挿すとその 1 本は途中で切れます。

要約に進むタイミングは 2 つだけです。0 時になっても自動では要約しません。

- その日の録音に動きが無いまま 30 分たつ（最後の取り込みや処理から。既定。設定の `session.idleCloseSeconds`）と、自動で要約します
- 待たずに要約したいときは、パネルの「状態」の「今すぐ要約」を押します。「要約を始めました（n 件）」と出ます（新しく要約する録音が無いときは「新しく要約する録音はありません」）

要約したあとに同じ日の録音が届くと、その日のノートを作り直します。

### できあがるもの

| ノート | 場所 | 中身 |
|---|---|---|
| Raw ノート | `Daily/Voice/Raw/<yyyymmdd>/` | 文字起こしの全文。時刻の見出し付き |
| Daily ノート | `Daily/Voice/Wiki/<yyyymmdd>/` | 要約・Timeline・キーポイント・タスク・決定事項・アイデア |

（Vault の中の既定の場所です。）

Raw ノートと Daily ノートは自動で作り直されます。**手で書き加えた内容は次の再生成で失われます。**書き足したいことは別のノートに書き、リンクで結んでください。

パネルの ⚙ →「一般」の「話者分離（誰が話したか）」をオンにすると、その後に文字起こしする録音の Raw ノートが `**話者A**: …` の行になります（既定はオフ）。話者の名前は付けず、録音（約 30 分）ごとに A・B… を振り直します。精度は録音の条件で変わるので、使うかどうかは試して決めてください。

Daily ノートの要約に使う指示（プロンプト）は、パネルの ⚙ →「要約プロンプトを編集…」で開く窓で変えられます。「1 回で要約」「分割して要約（Map）」「まとめ（Reduce）」の 3 つがあり、何も変えなければ同梱の既定の本文を使います。本文の中の `{schema_block}` と `{custom_instructions}` は消さないでください（消すと保存できません）。変更は次に要約する日から使い、要約済みの日は作り直しません。「既定に戻す」を押して保存すると元の本文に戻ります。

### 状況を見る

メニューバーのアイコンが状態を表します。

| アイコン | 状態 |
|---|---|
| 波形 | 待機中 |
| 下向きの矢印（丸） | 取り込み中 |
| 吹き出し | 文字起こし・要約中 |
| 三角の警告 | 要対応（上の 3 つより優先） |
| 赤い点（アイコンの右上に重なる） | 元音声の削除が有効 |

アイコンを押すとパネルが開きます。

- 「状態」: いまの動き、最終接続、未処理の件数と長さ、デバイスの空き容量。「今すぐ要約」もここです
- 「要対応」: 利用者が直すことがあるときだけ出ます。説明と、直すためのボタンが付きます
- 「詳細・診断」: 押すと「診断を実行」「LLM の疎通確認」、「状態の詳細」（Part と Session の状態別の件数、失敗した録音の一覧など）、ログと設定ファイルを Finder で表示するボタンが出ます

## 元音声の削除

**既定では削除しません。**デバイス上の録音はそのまま残ります。
**元音声の削除は、Raw ノートの検証を通った録音だけを対象にします。**要約（Daily ノート）は待ちません。要約は元音声を使わないためです。

### 三重ロック

| ロック | 内容 |
|---|---|
| 1. 設定 | アプリの設定と、削除モジュールの設定ファイルの**両方**で有効にする必要がある |
| 2-A. 実行できる場所に無い | 削除を行うプログラムは、有効化するまで**実行できる場所に置かれない**。置かれた後も、起動する前に毎回、署名と版を確かめる |
| 2-B. OS レベル | デバイスは**読み取り専用**で再マウントされる（有効にするまで、OS が書き込みを拒む） |

さらに、削除の判断（アプリ）と実行（別の実行ファイル）を分け、実行側が判断を信用せず **14 項目**を独立に再検証します。
片方だけ解除された状態は起動時に見つけて、安全な側（無効）へ揃えます。

### 削除の根拠

| 場所 | 確かめ方 |
|---|---|
| Obsidian の Raw ノート | 実ファイルを読み直してハッシュを照合し、その録音の鍵が載っていることを確認 |
| アプリの中の文字起こし JSON | **無期限に保持**され、Raw ノートの再生成元になる |

**どちらか一方でも欠けていれば削除しません。**
無音・重複と判定した録音は、**別の操作で有効にしない限り**消しません（有効にした後の「無音・重複も消す」。同じく赤いボタンの長押しです）。

### 有効にする

パネルの「元音声の削除」の行を押して画面を開きます。

1. 事前確認が出ます。「1 日以上の運用で Raw ノートが正しく作られていることを確かめましたか」と、最新の診断の結果です（無ければ「診断を実行」のボタンが出ます）
2. **赤い「有効にする」を 3 秒押し続けます。**クリック 1 回・チェックボックスでは有効になりません。途中で離すと取り消しです

**消した録音は戻りません。**

**読み書きできるようになるのはデバイスを挿し直した後です**（それまでは消えません）。
有効な間は、メニューバーのアイコンの右上に赤い点が**常に**出ます。パネルの「元音声の削除」の画面には、3 つのロックが個別に出ます。
有効にする前に溜まっていた録音は、パネルの「詳細・診断 → 過去分を削除対象にする」で後から対象にできます（**先に件数のプレビューが出ます**）。

### 元に戻す

**確認は求められません。**「無効にする」を押した時点で止まります。
止まる順は、消す能力に近いものからです。削除モジュールの設定を無効 → 削除モジュールを取り除く → アプリの設定を無効 → 未処理の削除要求を取り下げ → **接続中のデバイスを直ちに読み取り専用へ戻す**。
**挿し直しを待ちません。**（取り込みのコピーの最中に押したときは、コピーの区切りまで待つので、「読み取り専用へ戻しています…」と出たまま数分かかることがあります）

## 既知の制約

| # | 制約 | どうなるか |
|---|---|---|
| RK-07 | 送信機 2 台のときの動きは実機で確かめていない | 2 台でも扱える作りだが、保証はしない。同時に挿すと 2 台目は取り込まず、「はじめに」の⑤で案内する。1 台ずつ挿す |
| RK-18 | Raw / Daily ノートを手で編集すると、再生成で上書きされる | 書き足したいことは別のノートに書く。編集中は削除の根拠が崩れるので**元音声は消えない**（安全側） |
| RK-28 | 取り込みの後にボリューム名を変えると、それ以前の録音が削除対象から外れる | 使い始める前に名前を決める（「必要なもの」） |
| RK-31 | ちょうど 30 分で 0 文字になった録音を「無音」と判定しうる | 無音・重複の削除は既定で無効。文字起こしの JSON は残る |
| RK-32 | 使い始めた後にタイムゾーンを変えると、日付の境界がずれる | **使い始めた後に、設定のタイムゾーンを変えないでください。**すでに書いた記録は書き換えません |

v1 に無いものは、自動アップデート、通知センター、話者識別（声から人の名前を当てること。話者を A・B… に分ける話者分離はできます）、Intel Mac、Mac App Store 版です。

## 困ったとき

まずパネルの「詳細・診断 → 診断を実行」を押します。
診断は **17 件**（うち **1 件** は LLM への実リクエストで、別のボタンから実行します）。診断は**何も書き換えません**。

| 症状 | 見るところ |
|---|---|
| 録音が取り込まれない | 診断の DR-11（デバイスを列挙できるか）、パネルの「要対応」。デバイスの名前が `DJIMIC3` か（「はじめに」の 5 つ目） |
| ノートが書かれない | 診断の DR-10（Vault が使えるか）。Obsidian で Vault を一度開いたか |
| 文字起こしが始まらない | 診断の DR-04・DR-05・DR-06（whisper とモデル） |
| 要約が始まらない | 診断の DR-07・DR-08（llama-server とモデル、メモリ）。「LLM の疎通確認」ボタン（DR-09） |
| 途中で止まったように見える | パネルの「詳細・診断 → 状態の詳細」。失敗した録音は、次にデバイスをつなぐかアプリを起動し直すと**自動的に再試行**されます。すぐ試すなら「詳細・診断」の「再試行」 |
| 途中で電源が落ちた | **起動時に自動で巻き戻します。**完了した工程は飛ばすので二重処理しません |
| 削除が起きない | パネルの「元音声の削除」の 3 行（どのロックが掛かっているかが出ます）と診断の DR-14 |
| ビルドのたびに許可を聞かれる | 診断の DR-17（配布物ではなく自分でビルドしたものを使っていませんか） |

## データの置き場所

```text
~/Library/Application Support/VoiceDock/
```

- 設定（`config.json`）、データベース、取り込んだ音声と作業領域、文字起こし、ログ、モデル、削除モジュールの置き場所が、このフォルダの中に分かれて入ります。1 つずつのパスは `docs/PLAN.md` の §2.3 にあります
- アプリはここと Obsidian の Vault 以外には書きません
- アンインストールするときは、`/Applications` からアプリを消し、このフォルダを消します（**先に削除を無効にしてから**）

## 保守

- **バックアップ**: データベースは SQLite を WAL で開いているので、**単純なファイルコピーをしないでください**。Vault のノートと `transcripts/` があれば、Raw ノートは作り直せます
- **更新**: 新しい dmg を開いて `Applications` へ上書きします。許可は引き継がれます。**削除が有効なときは、削除モジュールの版もアプリに合わせて更新が要ります**。
  版が違うと削除が止まり、パネルに「削除モジュールの更新が必要です」と出ます。「元音声の削除」の画面の赤い「更新する」を 3 秒押し続けると、有効化の操作をもう一度通して入れ直します

## 開発

| コマンド | 内容 |
|---|---|
| `make test` | ディスクイメージと LLM 受け入れ試験を除く全テスト（削除禁止テスト → ポリシー → 残りの順。CI と同じ） |
| `make lint` | `swift format lint --strict` |
| `make app` | debug の `VoiceDock.app` を組み立てる（先に `make vendor` で whisper.cpp と llama.cpp をビルドしておく。版は `Vendor/versions.env`） |
| `make release` | 署名・公証・dmg（手元の Mac で行う。証明書は CI に置かない） |

- [docs/PLAN.md](docs/PLAN.md): 設計
- [docs/SPEC.md](docs/SPEC.md): 規範の表
- [docs/E2E.md](docs/E2E.md): 実機試験
- [docs/POC.md](docs/POC.md): 実測
- [docs/tickets/README.md](docs/tickets/README.md): タスク

矛盾する場合は `docs/PLAN.md` を優先します。

ディスクイメージのテストは CI では走らせません（CI は開発機のランナーで、実機が抜いてあることを保証できないため）。CI の削除禁止テストは、普通のディレクトリを相手にする層だけです。
削除に触れる PR では、実機を抜いたことを確かめてから手元で `make test-disk` を回し、その結果を PR に貼ります。
