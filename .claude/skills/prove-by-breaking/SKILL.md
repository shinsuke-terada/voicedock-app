# 破壊による証明（$ticket）

テストが通ったことは、テストが**何かを見ている**ことを意味しない。チケット §「破壊による証明」の表は「この 1 行を壊せば、この名前のテストが落ちる」という対応表で、それを実際に確かめた記録を PR 本文に貼る。

## 先にゲートを通す（飛ばさない）

`git checkout -- <file>` は**未コミットの変更を消す**。壊す前に、消えて困るものが無いことを確かめる。

```bash
git status --porcelain            # 出てくるのが、このチケットで自分が作ったファイルだけであること
git stash list | wc -l            # 本数を控えておく（終わったときに同じであること）
```

- `git status --porcelain` に**身に覚えの無いファイル**があれば、**止めて利用者に聞く**。勝手にコミットも stash もしない
- 並列で別のチケットが走っているなら、その作業ツリーを巻き込む。**並列中は破壊による証明をしない**か、自分のブランチだけであることを確かめる

## 1 項目ずつ

チケット §「破壊による証明」の表の行を、**1 回に 1 か所だけ**。

```bash
# 1. 壊す前: 差分が無いこと（真であること）
git diff --quiet -- <file> && echo "clean"

# 2. 表の「壊し方」のとおりに 1 か所だけ変える（Edit で）

# 3. 壊した後: 差分があること（偽であること）
git diff --quiet -- <file> || echo "broken"

# 4. テストを回す
make test

# 5. 落ちたテストの表示名を控える

# 6. 戻す
git checkout -- <file>
git diff --quiet -- <file> && echo "restored"
```

2 か所を同時に壊さない。どちらが効いたのか分からなくなる。

## 「壊したのに通った」ら

それがこの手順の目的。テストが空振りしている。

1. まず戻す（`git checkout -- <file>`）
2. そのふるまいを見るテストを**足すか直す**
3. 最初からやり直す

「たぶん別のテストが見ているはず」で済ませない。チケットの表が「このテストが落ちる」と名指ししているなら、そのテストが落ちなければ不合格。

## 終わったら

```bash
git status --porcelain            # 始める前と同じであること
git stash list | wc -l            # 控えた本数と同じであること
```

結果を PR 本文の「破壊による証明」の節に表で貼る。

| 壊し方 | 落ちたテスト |
|---|---|
| `Sources/…` の `…` を `…` に変える | `<実際に落ちたテストの表示名>` |

チケットの表の「落ちるべきテスト」と、実際に落ちたテストが**違っていた**ときは、そのことも書く。仕様かテストのどちらかがずれている。
