# Phase 0 PoC の測定と記録

仕様は `docs/tickets/P0-poc.md`（329 行）。成果物は **`docs/POC.md`** 1 本で、T-01 の最初のコミットに入る。使い捨ての実験コードは `~/VoiceDockPoC/` に置き、**リポジトリには入れない**。

$step が指定されていればその章だけを扱う。無ければ `docs/POC.md` の目次の表を見て、`⬜ 未実施` の一番上の章から進める。

## この工程がほかと違うところ

**Phase 0 は、このプロジェクトで唯一、実機の DJI Mic 3 に触れるフェーズ。** だから手順が二層に分かれている。

| 層 | 誰が | 例 |
|---|---|---|
| 自動でよい | エージェント | ディスクイメージ（`~/VoiceDockPoC/mnt/` に `-mountpoint` つきで attach）の実験、whisper / llama のビルドと計測、`sw_vers` などの環境の採取 |
| **【利用者が行う】** | 利用者 | 実機の接続・`diskutil` の観察・実機のファイルの削除・`-mountpoint` 無しの attach・TCC の許可ダイアログ・ログアウト / ログイン |

## 手順

### 1. `docs/POC.md` を用意する

無ければ `P0-poc.md` §0「記録の規約」のブロックと、続く 14 行の目次の表を**そのまま**写して作る。判定欄はすべて `⬜`。

### 2. 自動でよい部分をやる

`P0-poc.md` の該当章の手順どおりに実行する。ディスクイメージは必ず:

```bash
mkdir -p ~/VoiceDockPoC/mnt/PoCDJI
hdiutil create -quiet -size 64m -fs "MS-DOS FAT32" -volname PoCDJI ~/VoiceDockPoC/img.dmg
hdiutil attach -nobrowse -mountpoint ~/VoiceDockPoC/mnt/PoCDJI ~/VoiceDockPoC/img.dmg
```

`-mountpoint` を落とすと `/Volumes` に出る。ボリューム名に `VOICEDOCK`・`DJIMIC3` を使わない。

### 3. 実機の部分は「渡して止まる」

実機に触れる手順に来たら、**自分で実行しない**。次の形で提示して、**そこでターンを終える**:

```
【利用者が行う】P0-02 の「実機での確認」

1. 実機が挿さっていることを確かめる
2. 次をそのまま実行し、出力を全部そのまま貼り戻してください:

   <コマンドのブロック>

3. 見てほしいもの: <何を確かめるか>
4. 注意: この手順で消えてよいのは <…> だけです
```

利用者の返事を待つ。**待っている間に先回りして別の実機の手順を実行しない。**

### 4. 生の出力を記録する

返ってきた出力を `docs/POC.md` に**そのまま**貼る。要約した数値だけを書かない。

```markdown
### 3. P0-02 読み取り専用での再マウント

判定: ✅ PASS

測定日: 2026-09-21
コマンド:
```
<実行したコマンド>
```
出力:
```
<貼り戻された生の出力>
```
根拠: 出力の <n> 行目の `MNT_RDONLY` が …
限界: 代替手段で測ったため …
```

### 5. 判定を書く

判定は `✅ PASS` / `✗ FAIL` / `⬜ 未実施` / `— 対象外` のどれかで始める。空欄や散文にしない。目次の表の判定欄も同時に更新する。

**生の出力を受け取っていない行に判定を書かない。** 推測で `✅ PASS` を書くのは、この PoC が存在する理由そのものを壊す。分からなければ `⬜ 未実施` のまま残す。

## PLAN と食い違ったとき

`docs/POC.md` の冒頭にあるとおり、**実測値が正**。PLAN とチケットを直す PR を出す（`.claude/rules/workflow.md` の判断木）。Phase 0 の実測が PLAN を否定するのは想定の範囲内で、そのために先に測っている。

## 終わったら

- 章 14「Phase 0 で決めたこと」に `BUNDLE_ID` と `TEAM_ID`（`security find-identity` の括弧の中の 10 文字）を書く。これが T-01 の `identity.env` の前提になる
- 受け入れ条件（`P0-poc.md` §「受け入れ条件」）を 1 つずつ確かめる。特に「自動の手順が `/Volumes` 配下にマウント・書き込み・削除・再マウントをしていない」
- `~/VoiceDockPoC/` はリポジトリに入れない。入るのは `docs/POC.md` だけ
